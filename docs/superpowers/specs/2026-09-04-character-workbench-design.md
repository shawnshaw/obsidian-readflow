# ReadFlow 人物工作台设计

## 目标

让读者在整理摘录时显式关联人物，并在同一本书的人物工作台中快速回忆人物身份、查看证据摘录，以及维护人物关系。

## 范围

第一期仅支持单本书内的人物。不会自动从文本猜测人物、不会自动确认人物关系，也不会建立跨书人物库。

## 交互主张

摘录是人物记忆的证据，人物档案是阅读中的快速回忆入口，关系图只展示经过用户确认的人物关系。用户在同一个阅读工作台完成标记、回忆和梳理，而不是跳转到独立管理页。

## 信息地图

- 摘录编辑：原有“实体标签”保留；新增“人物（可选）”，用逗号关联人物。
- 人物工作台：人物名册按待补全与已整理显示；每行展示姓名、角色、一句话摘要、关联摘录数与关系数。
- 人物详情：编辑姓名、角色、一句话摘要、备注、首次登场摘录；查看关联摘录。
- 关系图谱：仅人物节点与手动关系边；点击人物聚焦其一跳关系；关系可关联一条证据摘录。

## 状态地图

- 空：没有显式人物时，引导用户在摘录编辑中添加人物。
- 待整理：人物由摘录自动创建，只有姓名和证据摘录。
- 已整理：人物补充了角色或摘要。
- 关系编辑：选择人物 A、人物 B、关系类型和可选证据摘录。
- 聚焦：图谱只保留选中人物及其直接关系。

## 数据设计

每条摘录新增可选 `characters: string[]`。当该字段存在时，它是人物模式的唯一来源；不存在时沿用旧 `entities` 字段，确保历史数据不消失。人物档案和关系继续复用每本书已有的 `entityProfiles`、`entityRelations`，以避免破坏现有数据。

人物名称按去空格、去重和不区分大小写的键进行归并；图中显示名称由档案的 `displayName` 优先决定。地点、概念等普通实体不会因为新增人物字段而进入人物图谱。

## 成功标准

- 编辑摘录时可单独填写人物，保存后自动出现在当前书的人物名册。
- 普通实体不再自动污染新摘录的人物关系图。
- 人物档案能显示其关联摘录数量，并能由关系图点击打开。
- 人物关系可手动建立并带可选证据摘录，图谱可按人物聚焦。
- 历史没有 `characters` 字段的摘录仍维持原有人物显示行为。
